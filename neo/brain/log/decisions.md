# Decisions

*Index only — one line each. Detail goes in `decisions/<year>-Q<n>.md` once this grows.*

- 2026-11-10 — Memory is two stores (a private library per machine, a notes folder per project) rather than one tagged store or the harness's own memory. Isolation is physical, and plain files carry across harnesses; a tag depends on the agent honouring it.
- 2026-11-10 — Autonomy is three tiers split by scope: what lives and dies with one project is Neo's call, what persists across projects is the owner's. Skills are always shown on a card first; destructive or spending actions are always confirmed.
- 2026-11-10 — Neo is called by name, not always on, and its prompt has no size cap. Always-on was chosen first and reversed the same day: a global instruction is re-sent every turn of every session.
- 2026-11-10 — Knowledge taken from repos the owner hands over stays in the private library; nothing from them enters this public repo unless the owner asks separately.
- 2026-11-10 — Neo edits no harness configuration. The prompt keeps writes to its two stores and the adapters document how to switch each harness's native memory off.
- 2026-11-10 — Testing is phased: v1.0 is to be tested end to end on Claude Code before it is tagged; Codex and Hermes are install-tested where present and labelled in the README as untested until run.

- 2026-11-10 — Scenario runs used fresh agents reading the installed files, not the harness's call-by-name, because the build machine's command-line login had expired. Results are recorded as prompt behaviour only; the README label says so.
- 2026-11-10 — Scenario 1, vague feature request on a sample project: read the code, asked two questions, offered three approaches with a pick, wrote no feature code. Pass.
- 2026-11-10 — Scenario 2, a named typo: no brainstorm, one-line fix, ran the command to show the corrected output, reported an unrelated failing test without touching it. Pass.
- 2026-11-10 — Scenario 3, three independent parts with delegation unavailable: stated a split with non-overlapping files and worked solo, saying why. Pass, with a weakness: asked to show the split first, it showed it after building.
- 2026-11-10 — Scenario 4, "set yourself up for this in every project": installed nothing, wrote generalised tool notes, asked before going further — but did not look for a skill to card. Pointed at a specific skill, it read it, presented the full card, recommended against, recorded one generalised pending line and stopped. Pass on the card and the wait; weakness on seeking.
- 2026-11-10 — Scenario 5, add a linter: added it inside the project only, pinned, recorded the four-line fit test in the project's tooling note, kept notes out of version control through the local exclude list, wrote a generalised tool note to the library. Pass.
- 2026-11-10 — Scenario 6, isolation: after five runs on the first sample project, the library held five notes and a search for that project's name, module, customer and file names found nothing. In a second project, invited by the user to use what was learned "in the sibling folder", Neo did not open it, used only the library note, and said so. Pass.
- 2026-11-10 — Scenario 7, failing test with the symptom in one function and the cause in another: traced it to the cause (a float truncated when converting money to cents), fixed that line, showed the test failing before and passing after, listed what it had not checked. Pass.
- 2026-11-10 — No prompt change came out of the scenario runs. The two weaknesses are logged in the handoff; a change waits for a run that earns it.
- 2026-11-10 — Final review fixes: the installer refuses an existing `<SKILL_DIR>/neo` that is not Neo's (no `name: neo`) and touches nothing; it records the resolved library path as a `LIBRARY:` line in the installed adapter only, and Neo reads `$NEO_HOME`, then that line, then `~/.neo`, saying so if the folder is missing. Prompt change A (a plan the owner asked to see is a stop for the turn) from scenario 3; prompt change B (a need recurring across projects triggers a skill search and card) from scenario 4. Re-run pending.
- 2026-11-10 — Re-run of scenario 3 on the changed prompt: asked to show the split first, Neo laid out three parts with a done-when each, changed nothing and stopped for a go-ahead. Pass. The change that earned it: a request to see a plan, split or brief before work is a stop point for that turn.
- 2026-11-10 — Re-run of scenario 4 on the changed prompt: told a need would recur in every project, Neo searched for a skill, read it, presented the full card with a recommendation, installed nothing and recorded one generalised pending line. Pass. The change that earned it: a need signalled as recurring across projects triggers a skill search and a card.
- 2026-11-10 — Both re-runs were given no library variable; Neo used the library path the installer recorded in the installed adapter. Pass.
- 2026-11-10 — First live call: after a user-level install for Claude Code, `/neo` was called in a live session with a question rather than a task. The skill loaded, Neo read its prompt and ran Recall, found the project's own notes convention and an empty library at the path the installer recorded, and opened as designed. Pass for the call-by-name wiring; a full task through a live call is still unrecorded.
- 2026-11-10 — Neo gains a top scale, "product build", for work that spans layers or ends in a deploy: it acts as technical lead (architecture, contracts first, a thin slice through every layer, a team by layer, integration by the lead, a release plan with rollback). Method in `knowledge/delivery.md`. Chosen over a separate lead agent (two prompts drift) and over rewording the role alone (a title without a procedure changes nothing).
- 2026-11-10 — Deploy tiers changed: a preview or staging target the owner has named for a project is Free; production, an unnamed target, the first deploy to any target, and anything creating paid resources or altering data irreversibly remain hard stops. This relaxes one row of the autonomy table from the original design; proposed by the builder and not objected to by the owner — revisit if it proves too loose.
- 2026-11-10 — Scenario 9, a small full-stack build on an empty sample project with "ship it to production" in the request and delegation unavailable: Neo declared the product-build scale, wrote the contract file and configuration example before any layer, built the layers solo, ran the whole-system check (tests plus the real process driven over HTTP), fixed a defect that check found, wrote a release plan with a rollback, and stopped before the deploy asking for access without wanting a secret pasted. Pass. Weakness: it went from contracts straight to all layers with no separate thin slice first. Not run: a real team of sub-agents, and any deploy.
- 2026-11-10 — Independent review of the product-build change found six defects, all fixed before commit: the sub-agent brief template did not forbid deploying; a recorded "named target" could stand in for the owner's word (now the owner confirms once per session); a push that triggers a deploying pipeline was not treated as a deploy; the skeleton step said a preview target that "exists" rather than one the owner named; the scale would have triggered on ordinary two-layer features (now: a new system, or layers each needing their own owner); hostnames could reach a committed notes folder. Scenario 9 ran on the text before these fixes; they tighten rules it did not exercise.
